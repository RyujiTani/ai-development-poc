## 概要
外注先管理者が打刻漏れ時に手動で打刻データの登録・修正を行う画面。
修正時には修正理由の入力が必須となる。

## 要件一覧

### 機能要件
| トレースID | 要件内容 | 優先度 | 備考 |
|---|---|---|---|
| SCR-009-FN-001 | 打刻漏れ時の手動打刻登録ができる | High | 要件定義書 4章 |
| SCR-009-FN-002 | 既存の打刻記録を修正できる | High | 要件定義書 4章 |
| SCR-009-FN-003 | 修正理由を入力できる | High | 修正理由の入力必須 |

### UI要件
| トレースID | 要件内容 | 備考 |
|---|---|---|
| SCR-009-UI-001 | 対象作業員選択欄、打刻日時入力欄、打刻種別（出勤/退勤）選択欄、修正理由入力欄を配置する | |
| SCR-009-UI-002 | レスポンシブWebデザインでPC/スマホ両対応とする | |
| SCR-009-UI-003 | スマホ利用時は入力欄・ボタンを大きくタップしやすいUIとする | 屋外操作を考慮 |

### バリデーション要件
| トレースID | 対象 | ルール |
|---|---|---|
| SCR-009-VL-001 | 対象作業員 | 必須選択。未選択の場合はエラーメッセージを表示する |
| SCR-009-VL-002 | 打刻日時 | 必須入力。有効な日時形式であること |
| SCR-009-VL-003 | 打刻種別 | 必須選択（出勤/退勤のいずれか） |
| SCR-009-VL-004 | 修正理由 | 必須入力。空文字の場合はエラーメッセージを表示する |
| SCR-009-VL-005 | 認証状態 | 未認証状態でアクセスした場合はログイン画面（SCR-001）へリダイレクトする |

### イベント・遷移要件
| トレースID | トリガー | 挙動 |
|---|---|---|
| SCR-009-EV-001 | 「送信」ボタン押下かつバリデーション成功 | 打刻修正データを送信し、完了メッセージを表示後、外注先ホーム画面（SCR-002）へ遷移する |
| SCR-009-EV-002 | 「キャンセル」ボタン押下 | 外注先ホーム画面（SCR-002）へ遷移する |

### データ要件
| トレースID | 種別 | 内容 |
|---|---|---|
| SCR-009-DT-001 | API（送信） | POST /api/punches/correction — リクエスト: { worker_id, punch_type, punched_at, reason } |

## 実装・テストへの引き継ぎ指示
- コード生成時は各実装箇所のコメントに対応するトレースIDを必ず記載すること
  例: `// trace: SCR-009-FN-003`
- テスト生成時はテスト名・describeにトレースIDを含めること
  例: `describe('SCR-009-VL-004: 修正理由必須バリデーション', ...)`
- 1つの実装/テストが複数IDをカバーする場合はカンマ区切りで列挙すること

## 確認事項
- 外注先管理者による打刻修正に工場側管理者の承認フローが必要か（要件定義書 3章に「シンプルに工場側管理者が修正・確認可能」とあるが、承認ステータスの管理要否が未確定）。
- 打刻修正画面への導線（ホーム画面のメニューに含めるか、打刻フロー中に配置するか）が要件定義書に未記載。[ASSUMPTION] ホーム画面から遷移可能とする。
