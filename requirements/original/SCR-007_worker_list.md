## 概要
外注先管理者が自社に所属する登録済み作業員のリストを閲覧・管理する画面。
作業員の追加・編集・削除への導線を提供する。

## 要件一覧

### 機能要件
| トレースID | 要件内容 | 優先度 | 備考 |
|---|---|---|---|
| SCR-007-FN-001 | ログイン中の外注先管理者の所属企業に紐づく作業員一覧を表示できる | High | 氏名、連絡先、資格の有無、講習受講履歴を表示 |
| SCR-007-FN-002 | 作業員の新規追加画面へ遷移できる | High | |
| SCR-007-FN-003 | 既存の作業員の編集画面へ遷移できる | High | |
| SCR-007-FN-004 | 既存の作業員を削除できる | High | 要件定義書 2章「登録・変更・削除」 |

### UI要件
| トレースID | 要件内容 | 備考 |
|---|---|---|
| SCR-007-UI-001 | 作業員をリスト形式で表示する（氏名、資格情報等の主要項目を表示） | |
| SCR-007-UI-002 | 一覧はページネーションまたは無限スクロールで表示する | 要件定義書 6章 |
| SCR-007-UI-003 | 「新規追加」ボタンをリスト上部に配置する | |
| SCR-007-UI-004 | 各作業員行に「編集」「削除」の操作ボタンを配置する | |
| SCR-007-UI-005 | レスポンシブWebデザインでPC/スマホ両対応とする | |
| SCR-007-UI-006 | スマホ利用時はボタンを大きくタップしやすいUIとする | 屋外操作を考慮 |

### バリデーション要件
| トレースID | 対象 | ルール |
|---|---|---|
| SCR-007-VL-001 | 削除操作 | 削除前に確認ダイアログを表示する [ASSUMPTION] |
| SCR-007-VL-002 | 認証状態 | 未認証状態でアクセスした場合はログイン画面（SCR-001）へリダイレクトする |

### イベント・遷移要件
| トレースID | トリガー | 挙動 |
|---|---|---|
| SCR-007-EV-001 | 「新規追加」ボタン押下 | 作業員追加・編集画面（SCR-008）を新規追加モードで開く |
| SCR-007-EV-002 | 作業員行の「編集」ボタン押下 | 作業員追加・編集画面（SCR-008）を編集モードで開き、該当作業員情報をロードする |
| SCR-007-EV-003 | 作業員行の「削除」ボタン押下かつ確認OK | 該当作業員を削除し、一覧を更新する |
| SCR-007-EV-004 | 戻るボタン押下 | 外注先ホーム画面（SCR-002）へ遷移する |

### データ要件
| トレースID | 種別 | 内容 |
|---|---|---|
| SCR-007-DT-001 | API（取得） | GET /api/workers — 所属企業に紐づく作業員一覧を取得する |
| SCR-007-DT-002 | API（削除） | DELETE /api/workers/{worker_id} — 指定した作業員を削除する |

## 実装・テストへの引き継ぎ指示
- コード生成時は各実装箇所のコメントに対応するトレースIDを必ず記載すること
  例: `// trace: SCR-007-FN-004`
- テスト生成時はテスト名・describeにトレースIDを含めること
  例: `describe('SCR-007-EV-003: 作業員削除', ...)`
- 1つの実装/テストが複数IDをカバーする場合はカンマ区切りで列挙すること

## 確認事項
- 削除は物理削除か論理削除か未定。データ保持期間（5年）の要件との整合性を確認する必要あり。
