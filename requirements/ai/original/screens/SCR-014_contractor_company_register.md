## 概要
工場側管理者が外注先企業の情報を登録・管理する画面。
外注先企業の一覧表示、新規登録、編集、削除を行う。

## 要件一覧

### 機能要件
| トレースID | 要件内容 | 優先度 | 備考 |
|---|---|---|---|
| SCR-014-FN-001 | 登録済みの外注先企業一覧を表示できる | High | 要件定義書 4章 |
| SCR-014-FN-002 | 外注先企業を新規登録できる | High | 要件定義書 3章「外注先企業を登録する」 |
| SCR-014-FN-003 | 既存の外注先企業情報を編集できる | High | [ASSUMPTION] |
| SCR-014-FN-004 | 外注先企業を削除できる | Mid | [ASSUMPTION] |

### UI要件
| トレースID | 要件内容 | 備考 |
|---|---|---|
| SCR-014-UI-001 | 外注先企業をリスト/テーブル形式で表示する | |
| SCR-014-UI-002 | 「新規登録」ボタンをリスト上部に配置する | |
| SCR-014-UI-003 | 各企業行に「編集」「削除」の操作ボタンを配置する | |
| SCR-014-UI-004 | 新規登録・編集時はモーダルまたはインラインフォームで入力欄を表示する | [ASSUMPTION] |
| SCR-014-UI-005 | 一覧はページネーションまたは無限スクロールで表示する | 要件定義書 6章 |
| SCR-014-UI-006 | レスポンシブWebデザインでPC/スマホ両対応とする | |

### バリデーション要件
| トレースID | 対象 | ルール |
|---|---|---|
| SCR-014-VL-001 | 企業名 | 必須入力。空文字の場合はエラーメッセージを表示する |
| SCR-014-VL-002 | 削除操作 | 削除前に確認ダイアログを表示する [ASSUMPTION] |
| SCR-014-VL-003 | 認証状態 | 未認証状態または管理者権限がない状態でアクセスした場合は管理者ログイン画面（SCR-010）へリダイレクトする |

### イベント・遷移要件
| トレースID | トリガー | 挙動 |
|---|---|---|
| SCR-014-EV-001 | 「新規登録」ボタン押下 | 外注先企業情報の入力フォームを表示する |
| SCR-014-EV-002 | 登録/更新フォームの「保存」ボタン押下かつバリデーション成功 | 外注先企業情報を登録/更新し、一覧を更新する |
| SCR-014-EV-003 | 「編集」ボタン押下 | 該当企業の情報を入力フォームにロードして表示する |
| SCR-014-EV-004 | 「削除」ボタン押下かつ確認OK | 該当外注先企業を削除し、一覧を更新する |

### データ要件
| トレースID | 種別 | 内容 |
|---|---|---|
| SCR-014-DT-001 | API（取得） | GET /api/admin/contractors — 外注先企業一覧を取得する |
| SCR-014-DT-002 | API（登録） | POST /api/admin/contractors — 外注先企業を新規登録する。リクエスト: { company_name, ... } |
| SCR-014-DT-003 | API（更新） | PUT /api/admin/contractors/{contractor_id} — 外注先企業情報を更新する |
| SCR-014-DT-004 | API（削除） | DELETE /api/admin/contractors/{contractor_id} — 外注先企業を削除する |

## 実装・テストへの引き継ぎ指示
- コード生成時は各実装箇所のコメントに対応するトレースIDを必ず記載すること
  例: `// trace: SCR-014-FN-002`
- テスト生成時はテスト名・describeにトレースIDを含めること
  例: `describe('SCR-014-VL-001: 企業名必須バリデーション', ...)`
- 1つの実装/テストが複数IDをカバーする場合はカンマ区切りで列挙すること

## 確認事項
- 外注先企業情報の具体的な項目（企業名以外に住所、連絡先、代表者名等が必要か）が未定。
- 企業に紐づく作業員が存在する場合の削除可否のルールが未定。
