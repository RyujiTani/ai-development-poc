## 概要
工場側管理者がPCからID/パスワードを入力してシステム管理画面にログインするための画面。

## 要件一覧

### 機能要件
| トレースID | 要件内容 | 優先度 | 備考 |
|---|---|---|---|
| SCR-010-FN-001 | IDとパスワードによるログイン認証ができる | High | ID/パスワード認証（要件定義書 7章セキュリティ） |

### UI要件
| トレースID | 要件内容 | 備考 |
|---|---|---|
| SCR-010-UI-001 | ID入力欄・パスワード入力欄・ログインボタンを画面中央に配置する | |
| SCR-010-UI-002 | レスポンシブWebデザインでPC/スマホ両対応とする | PC利用が主 |

### バリデーション要件
| トレースID | 対象 | ルール |
|---|---|---|
| SCR-010-VL-001 | ID | 必須入力。空文字の場合はエラーメッセージを表示する |
| SCR-010-VL-002 | パスワード | 必須入力。空文字の場合はエラーメッセージを表示する |
| SCR-010-VL-003 | 認証 | ID/パスワードの組み合わせが不正な場合はエラーメッセージを表示する |

### イベント・遷移要件
| トレースID | トリガー | 挙動 |
|---|---|---|
| SCR-010-EV-001 | ログインボタン押下かつ認証成功 | 総合ダッシュボード（SCR-011）へ遷移する |
| SCR-010-EV-002 | ログインボタン押下かつ認証失敗 | 同画面にエラーメッセージを表示する |

### データ要件
| トレースID | 種別 | 内容 |
|---|---|---|
| SCR-010-DT-001 | API（送信） | POST /api/admin/auth/login — リクエスト: { id, password }、レスポンス: { token, admin_info } |
| SCR-010-DT-002 | ストレージ | 認証トークンをブラウザに保持する [ASSUMPTION] JWT等のトークン方式を想定 |

## 実装・テストへの引き継ぎ指示
- コード生成時は各実装箇所のコメントに対応するトレースIDを必ず記載すること
  例: `// trace: SCR-010-FN-001`
- テスト生成時はテスト名・describeにトレースIDを含めること
  例: `describe('SCR-010-VL-003: 認証失敗時エラー表示', ...)`
- 1つの実装/テストが複数IDをカバーする場合はカンマ区切りで列挙すること

## 確認事項
- 外注先ログイン画面（SCR-001）と管理者ログイン画面を同一画面で権限切り替えとするか、別画面とするかの最終確認が必要。[ASSUMPTION] 要件定義書 6章に別画面として記載されているため別画面とする。
- パスワードリセット機能の要否が未定。
