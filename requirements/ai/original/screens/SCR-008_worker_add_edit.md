## 概要
外注先管理者が作業員の情報（氏名、連絡先、資格の有無、講習受講履歴など）を新規登録または編集する画面。
新規追加モードと編集モードの2つの表示モードを持つ。

## 要件一覧

### 機能要件
| トレースID | 要件内容 | 優先度 | 備考 |
|---|---|---|---|
| SCR-008-FN-001 | 作業員の氏名を入力・登録できる | High | |
| SCR-008-FN-002 | 作業員の連絡先を入力・登録できる | High | |
| SCR-008-FN-003 | 作業員の資格の有無を入力・登録できる | High | 要件定義書 4章 |
| SCR-008-FN-004 | 作業員の講習受講履歴を入力・登録できる | High | 要件定義書 4章 |
| SCR-008-FN-005 | 編集モードでは既存の作業員情報をフォームに初期表示して更新できる | High | |

### UI要件
| トレースID | 要件内容 | 備考 |
|---|---|---|
| SCR-008-UI-001 | フォーム形式で各入力項目を縦並びに配置する | スマホでの入力を考慮 |
| SCR-008-UI-002 | 「保存」ボタンと「キャンセル」ボタンを配置する | |
| SCR-008-UI-003 | レスポンシブWebデザインでPC/スマホ両対応とする | |
| SCR-008-UI-004 | スマホ利用時は入力欄・ボタンを大きくタップしやすいUIとする | 屋外操作を考慮 |

### バリデーション要件
| トレースID | 対象 | ルール |
|---|---|---|
| SCR-008-VL-001 | 氏名 | 必須入力。空文字の場合はエラーメッセージを表示する |
| SCR-008-VL-002 | 連絡先 | 必須入力 [ASSUMPTION]。適切な形式であること |
| SCR-008-VL-003 | 認証状態 | 未認証状態でアクセスした場合はログイン画面（SCR-001）へリダイレクトする |

### イベント・遷移要件
| トレースID | トリガー | 挙動 |
|---|---|---|
| SCR-008-EV-001 | 「保存」ボタン押下かつバリデーション成功（新規追加モード） | 作業員を新規登録し、作業員一覧画面（SCR-007）へ遷移する |
| SCR-008-EV-002 | 「保存」ボタン押下かつバリデーション成功（編集モード） | 作業員情報を更新し、作業員一覧画面（SCR-007）へ遷移する |
| SCR-008-EV-003 | 「キャンセル」ボタン押下 | 作業員一覧画面（SCR-007）へ遷移する |

### データ要件
| トレースID | 種別 | 内容 |
|---|---|---|
| SCR-008-DT-001 | API（取得） | GET /api/workers/{worker_id} — 編集モード時に既存の作業員情報を取得する |
| SCR-008-DT-002 | API（登録） | POST /api/workers — 新規作業員を登録する。リクエスト: { name, contact, qualifications[], training_history[] } |
| SCR-008-DT-003 | API（更新） | PUT /api/workers/{worker_id} — 既存の作業員情報を更新する |

## 実装・テストへの引き継ぎ指示
- コード生成時は各実装箇所のコメントに対応するトレースIDを必ず記載すること
  例: `// trace: SCR-008-FN-003`
- テスト生成時はテスト名・describeにトレースIDを含めること
  例: `describe('SCR-008-VL-001: 氏名必須バリデーション', ...)`
- 1つの実装/テストが複数IDをカバーする場合はカンマ区切りで列挙すること

## 確認事項
- 資格・講習受講履歴の具体的な入力形式（自由記述 / マスタからの選択 / 複数件登録可否）が未定。
- 連絡先の具体的な項目（電話番号、メールアドレス等）が未定。
