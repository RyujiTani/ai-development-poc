## 概要
外注先管理者が端末のカメラを起動し、対象作業員の写真を撮影してプレビュー確認後、打刻データを送信する画面。
なりすまし防止のための証拠写真撮影を兼ねる。

## 要件一覧

### 機能要件
| トレースID | 要件内容 | 優先度 | 備考 |
|---|---|---|---|
| SCR-005-FN-001 | 端末のカメラを起動して写真を撮影できる | High | HTML5 Camera API等を利用（要件定義書 4章） |
| SCR-005-FN-002 | 撮影した写真のプレビューを表示できる | High | |
| SCR-005-FN-003 | プレビュー確認後、撮り直し（再撮影）ができる | High | [ASSUMPTION] |
| SCR-005-FN-004 | 送信ボタン押下で打刻データ（写真・打刻モード・対象作業員・打刻日時）をサーバーに送信できる | High | |
| SCR-005-FN-005 | クライアント側で画像圧縮処理を行い送信する | High | 要件定義書 7章性能要件。回線が細い環境でもエラーになりにくくするため |

### UI要件
| トレースID | 要件内容 | 備考 |
|---|---|---|
| SCR-005-UI-001 | カメラプレビュー領域を画面中央に大きく表示する | |
| SCR-005-UI-002 | 撮影ボタン・送信ボタン・撮り直しボタンを大きくタップしやすいサイズで配置する | 屋外操作を考慮 |
| SCR-005-UI-003 | 選択中の打刻モード（出勤/退勤）と対象作業員数を画面上部に表示する | |
| SCR-005-UI-004 | レスポンシブWebデザインでPC/スマホ両対応とする | |

### バリデーション要件
| トレースID | 対象 | ルール |
|---|---|---|
| SCR-005-VL-001 | 写真 | 写真が撮影されていない状態では送信ボタンを押下できない |
| SCR-005-VL-002 | カメラ権限 | ブラウザのカメラ利用権限が拒否された場合はエラーメッセージを表示し、権限許可を促す |
| SCR-005-VL-003 | 認証状態 | 未認証状態でアクセスした場合はログイン画面（SCR-001）へリダイレクトする |

### イベント・遷移要件
| トレースID | トリガー | 挙動 |
|---|---|---|
| SCR-005-EV-001 | 撮影ボタン押下 | カメラで写真を撮影し、プレビューを表示する |
| SCR-005-EV-002 | 撮り直しボタン押下 | プレビューをクリアし、カメラを再起動する |
| SCR-005-EV-003 | 送信ボタン押下かつ送信成功 | 完了画面（SCR-006）へ遷移する |
| SCR-005-EV-004 | 送信ボタン押下かつ送信失敗 | エラーメッセージを表示し、再送信を促す |
| SCR-005-EV-005 | 戻るボタン押下 | 作業員選択画面（SCR-004）へ遷移する |

### データ要件
| トレースID | 種別 | 内容 |
|---|---|---|
| SCR-005-DT-001 | API（送信） | POST /api/punches — リクエスト: { worker_ids[], punch_type(出勤/退勤), photo(圧縮済み画像), punched_at(打刻日時) } |
| SCR-005-DT-002 | 画像処理 | クライアント側で画像を圧縮してから送信する。レスポンス3秒以内を目標とする |

## 実装・テストへの引き継ぎ指示
- コード生成時は各実装箇所のコメントに対応するトレースIDを必ず記載すること
  例: `// trace: SCR-005-FN-001`
- テスト生成時はテスト名・describeにトレースIDを含めること
  例: `describe('SCR-005-VL-001: 写真未撮影時の送信防止', ...)`
- 1つの実装/テストが複数IDをカバーする場合はカンマ区切りで列挙すること

## 確認事項
- 複数人の作業員を一度に撮影した場合の処理方法が未決事項（要件定義書 9章）。現時点では「証拠写真」として1枚を全員に紐づけて保存する想定。
- オフライン時の挙動が未決事項（要件定義書 9章）。Service Worker等での一時保存を行うか原則オンライン必須とするか。
- 画像圧縮の目標サイズ・解像度が未定。
